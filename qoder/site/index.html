    它是怎么工作的

    1. 按讲义结构切块

      先按 Markdown 标题切节，把章节路径（第 4 讲 / 4.2 B+ 树为什么适合做磁盘索引）一起存下来；再在节内按段落聚合成约 700 字的块，相邻块保留 100 字重叠，避免答案被切在边界上。

    2. 两路同时召回

      向量通道取余弦距离最近的 40 条（HNSW 近似检索），全文通道取 MATCH … AGAINST 得分最高的 40 条。前者认语义，后者认字面。

    3. 按名次融合

      两条通道的分数不可比，所以只比名次：1 / (60 + rank) 相加后重排。同一个块被两路同时命中，得分自然更高。

    seekdb 承担了哪一部分

    检索层没有引入额外的向量库：表格里的全文索引、向量索引、相似度排序、标量过滤全部由 seekdb 完成，应用只负责切块、取 embedding 和融合排序。

    seekdb 能力与对应 SQL
    能力实现
    中文全文索引FULLTEXT KEY ft_content(content) WITH PARSER ik
    向量索引VECTOR INDEX vidx_vec(content_vec) WITH (distance=cosine, type=hnsw)
    语义召回ORDER BY cosine_distance(content_vec, %s) APPROXIMATE LIMIT 40
    字面召回WHERE MATCH(content) AGAINST(%s)，返回值即相关度
    按课程过滤WHERE course = %s 与向量排序写在同一条 SQL 里

    本地复现

    # 1. 装依赖
pip install -r requirements.txt

# 2. 配置 .env（embedding 服务 + seekdb 连接），建表在导入时自动完成
cp .env.example .env

# 3. 导入讲义
python -m src.ingest samples/database --course 数据库系统
python -m src.ingest samples/os --course 操作系统

# 4. 检索（命令行 / 网页）
python -m src.search "B+ 树为什么适合做索引"
python -m uvicorn src.web:app --port 8010

# 5. 跑验证样例
python -m eval.run_eval
