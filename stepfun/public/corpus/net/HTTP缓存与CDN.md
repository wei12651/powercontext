# 第 6 讲 HTTP 缓存与 CDN

## 6.1 强缓存与协商缓存

强缓存不需要向服务器发请求，浏览器直接使用本地副本，由 Cache-Control 的 max-age 或 Expires 控制。协商缓存会带上 If-None-Match 或 If-Modified-Since，服务器返回 304 时复用本地内容。

两者的选择取决于资源变化频率。带哈希文件名的静态资源适合设置一年的强缓存，因为内容变化时 URL 也会变；HTML 入口文件适合 no-cache 加协商缓存，保证每次都能拿到最新的资源引用。

## 6.2 ETag 与 Last-Modified 的差异

Last-Modified 精度是秒，一秒内多次修改无法区分；它也无法反映内容是否真的变化，只修改了修改时间但内容没变时会误判。ETag 基于内容摘要，更精确，但计算有开销，分布式环境下不同节点生成的 ETag 还可能不一致。

优先级上，ETag 高于 Last-Modified。如果同时提供，浏览器会发送两个验证头，服务器应以 ETag 为准。对动态内容，可以用弱 ETag 表示语义等价，避免逐字节比较。

## 6.3 CDN 的缓存键与回源

CDN 节点根据缓存键判断命中，缓存键通常包含 URL、查询参数、Host 和部分请求头。把无关参数纳入缓存键会降低命中率，把有意义的参数排除又会串内容。常见做法是只保留白名单参数。

回源策略决定未命中时如何取内容：可以直接回源站，也可以回上层节点。多级缓存能减少源站压力，但会增加首次访问的延迟。预热和刷新接口用于主动推送或失效内容，刷新通常按 URL 或目录进行。

## 6.4 边缘计算与动态加速

静态资源适合缓存在边缘，动态请求则依赖回源链路的优化。动态加速通过就近接入、协议优化和多路复用来降低跨地域延迟，但无法缓存业务数据。

边缘计算把部分逻辑下沉到 CDN 节点，例如鉴权、A/B 测试、图片处理。好处是延迟低，代价是状态管理复杂：边缘节点数量多，无法像中心机房那样维护强一致的状态，通常只做无状态计算。

## 6.5 缓存穿透、击穿与雪崩

缓存穿透指查询不存在的数据，请求每次都打到数据库。解决办法是缓存空值并设置较短过期时间，或者用布隆过滤器提前拦截。

缓存击穿指热点键过期瞬间大量请求同时回源。解决办法是互斥锁只让一个请求回源，或者热点键永不过期并由后台异步更新。缓存雪崩指大量键同时过期，解决办法是给过期时间加随机抖动，并做好多级缓存与限流降级。
