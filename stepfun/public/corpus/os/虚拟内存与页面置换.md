# 第 3 讲 虚拟内存与页面置换

## 3.1 为什么需要虚拟内存

虚拟内存给每个进程一个独立的地址空间，好处有三点：进程之间互不干扰，一个进程崩溃不会直接踩坏另一个；程序可以使用比物理内存更大的地址空间，超出部分暂存在磁盘上；链接和加载变得简单，程序不必关心自己最终落在物理内存的哪个位置。

实现靠页表：虚拟地址被拆成页号和页内偏移，MMU 用页号查页表得到物理页框号，再拼上偏移。页表项里除了物理地址，还记录有效位、脏位、访问位和权限位。

## 3.2 缺页中断

访问的页不在物理内存时触发缺页中断，内核介入：如果地址非法直接终止进程；如果是合法访问但页面在磁盘上，就找一个空闲页框（没有空闲就挑一个牺牲页换出），把内容读进来、更新页表、重新执行那条指令。

缺页率直接决定性能。物理页框够用的时候缺页只发生在冷启动；一旦工作集超过可用页框，就会进入「抖动」（thrashing），系统把大部分时间花在换入换出上，CPU 利用率反而下降。

## 3.3 局部性原理

页面置换策略成立的前提是局部性：时间局部性指刚访问过的数据很可能再次被访问，空间局部性指访问某个地址后邻近地址很可能被访问。数组顺序遍历、循环体反复执行都是典型的局部性表现。

因此置换算法的目标不是「预测未来」，而是「用历史近似未来」：保留最近刚用过、且很可能还要用的页。这也解释了为什么顺序扫描大文件会污染缓存——它只带来一次性的空间局部性，却把有用的热页挤出去。

## 3.4 常见页面置换算法

FIFO 按进入内存的先后淘汰，实现最简单，但存在 Belady 异常：增加物理页框后缺页次数反而上升，因为它不看访问频率。

LRU 淘汰最久未使用的页，符合局部性，效果通常最好。问题是精确实现需要每次访问都更新链表或时间戳，硬件支持和开销都不小；而且对「周期性扫描」不友好，一次大扫描会把热页全部淘汰。

Clock（近似 LRU）用一个环形队列加访问位：指针扫过时，访问位为 1 就清零并跳过，为 0 就直接淘汰。它用很少的开销逼近 LRU，是实际系统的常见选择。

OPT（最佳置换）淘汰未来最长时间不会被访问的页，缺页次数理论最少，但需要预知未来，只能作为评测其他算法的下界参考。

## 3.5 工作集与分配策略

工作集指进程在一段时间窗口内实际访问到的页集合。操作系统给进程分配的页框数如果小于工作集大小，进程必然频繁缺页。

常见的处理思路有两种：一是固定分配，按进程规模给固定页框数，简单但适应性差；二是动态调整，监测缺页率，缺页率过高就多给页框，过低就回收一些，把内存让给真正需要的进程。
