# 第 7 讲 进程调度与并发控制

## 7.1 调度器要平衡的三件事

调度器在三个目标之间取舍：吞吐量、响应时间和公平性。批处理场景希望减少上下文切换，让 CPU 尽量跑满；交互式场景希望任务尽快得到响应，哪怕牺牲一点吞吐；多用户场景还要防止某个进程长期霸占 CPU。

上下文切换本身有成本：保存寄存器、刷新 TLB、切换内核栈，一次大约几微秒。切换过于频繁会把时间花在切换上而不是干活上，所以调度的时间片不能太小。

## 7.2 常见调度算法

先来先服务（FCFS）实现简单，但长任务会阻塞后面的短任务，平均等待时间很差。短作业优先（SJF）能让平均等待时间最短，但需要预知运行时间，实际系统用指数平均来预测。

时间片轮转（RR）给每个进程固定时间片，交互响应有保证，代价是时间片越小切换越多。多级反馈队列（MLFQ）把进程按优先级分到多个队列，用完时间片就降级，短任务自然留在高优先级队列，是通用操作系统的常见选择。

## 7.3 优先级反转与继承

高优先级任务等待低优先级任务持有的锁，而低优先级任务又被中优先级任务抢占，导致高优先级任务被间接阻塞，这就是优先级反转。火星探路者号曾因这个问题反复重启。

解决办法是优先级继承：持有锁的低优先级任务临时提升到等待者的优先级，释放锁后恢复。另一种是优先级天花板：锁的优先级设为所有可能持有者的最高值，获取锁时直接提升。

## 7.4 竞态条件与同步原语

竞态条件的根源是「检查与使用之间存在时间窗口」。两个线程同时判断某个变量为 0 再自增，结果只加了一次。解决办法是把检查和修改做成原子操作，或者用锁保护临界区。

互斥锁适合临界区较长的场景；自旋锁适合临界区极短且 CPU 核数足够的场景，因为自旋不释放 CPU，等待时间长会浪费算力。信号量用于控制并发数量，条件变量用于等待某个条件成立，两者常配合互斥锁使用。

## 7.5 死锁的四个必要条件

死锁需要同时满足：互斥、持有并等待、不可剥夺、循环等待。破坏任意一个条件就能避免死锁。工程上最常见的是破坏循环等待：给所有锁定义全局顺序，按顺序加锁。

死锁检测通常用资源分配图找环，发现环后选择一个牺牲者回滚。死锁预防则更保守，比如一次性申请所有资源，代价是资源利用率下降。实际系统往往组合使用：设计阶段定顺序，运行时设超时，超时后回滚重试。
