# 第 5 讲 事务与隔离级别

## 5.1 ACID 与并发问题

事务要保证原子性、一致性、隔离性、持久性。并发执行时如果隔离性不够，会出现三类现象：脏读（读到别人未提交的数据）、不可重复读（同一事务内两次读到的值不同）、幻读（同一范围查询两次得到的行数不同）。

注意区分不可重复读和幻读：前者针对已存在的行被修改，后者针对新插入的行被发现。这个区别直接决定用行锁还是间隙锁。

## 5.2 四种隔离级别

读未提交允许脏读，几乎不用。读已提交只看到已提交的数据，解决了脏读，但同一事务两次读可能不同，常见于 Oracle、PostgreSQL 的默认配置。可重复读在事务开始时确定快照，解决了不可重复读，是 MySQL 和 seekdb 的默认级别。串行化通过加锁让事务串行执行，代价最大。

## 5.3 MVCC 是怎么实现的

多版本并发控制把「读」和「写」解耦：写操作不覆盖旧版本，而是产生新版本，读操作按自己的视图挑选可见版本，于是读不加锁、写不阻塞读。

实现上一般靠三样东西：每行上的事务版本号（创建版本和删除版本）、事务开始时的一致性快照、以及 undo 日志里的旧版本链。读取时沿着版本链回溯，找到第一个对当前事务可见的版本。

在读已提交级别下，每条语句执行前重新取一次快照，所以能看到别的事务新提交的修改；在可重复读级别下，快照在事务第一条语句时确定并保持不变，所以两次读结果一致。

## 5.4 锁：行锁、间隙锁与临键锁

InnoDB 风格的行级锁有几种形态。记录锁锁住索引上的一条记录；间隙锁锁住两个索引值之间的空隙，用来阻止插入；临键锁是记录锁加它前面的间隙，是范围扫描的默认加锁方式。

间隙锁只在可重复读级别生效，它的作用是解决幻读：锁住间隙后别的事务无法插入。代价是锁范围变大，容易冲突，而且间隙锁之间彼此不互斥（它们的目的都是阻止插入，不是互相排斥）。

死锁的典型场景是两个事务以相反顺序锁多行。处理办法是让所有事务按固定顺序访问资源，或者缩小事务粒度、降低持锁时间。数据库本身通常会检测到环路并回滚代价较小的事务。

## 5.5 日志：redo 与 undo

redo 日志保证持久性：修改先写日志再写数据页，崩溃重启后按日志重放。这是 WAL（预写日志）思想，把随机写数据页变成顺序写日志。

undo 日志保证原子性和 MVCC：回滚时按 undo 恢复旧值，读取旧版本时也从 undo 里取。两套日志职责不同，不要混淆——redo 记录「改成了什么」，undo 记录「改之前是什么」。
